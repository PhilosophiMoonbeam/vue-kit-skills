# Changelog

## Unreleased

### Changed

- Fixed local FileUpload replacement feedback when basic-mode validation emits an empty accepted queue; pending reads remain invalidated rather than leaving stale success or “Reading” state.
- Hardened the standalone Nuxt theme-cookie readers with null-safe, guarded decoding and a runtime allowlist. Malformed URI encoding no longer aborts SSR; unknown preferences resolve deterministically to light, and normal actions write canonical values.
- Made local IndexedDB rename/delete decisions compare the displayed snapshot inside their write transaction; stale cross-tab decisions cannot overwrite or delete newer records. Serialized overlay decisions through transition cleanup, restored outcome focus only after persistence and portal completion, and made finished-transaction aborts safe without pretending to undo committed work. Initial storage failure now exits the loading status.
- Made **New plan** clear its draft and invalidate review while preserving committed records and ordinary tab-switch drafts. Disabled router-menu destinations no longer retain live navigation links; Toast event distinctions remain explicit.

- Expanded optional OpenVue authoring coverage into eight focused references: selection/architecture, Vite/Nuxt setup, theming/pass-through, forms, data, overlays/services, navigation, and layout/media/utilities. The current index contains **48 references**; Quasar retains its separate incumbent route. Coverage reconciles the pinned 122-page official corpus with published **1.0.0** declarations/runtime, without implying future-major compatibility or unrecorded execution/publication.

- Adopted **OpenVue 1.x and newer** as the designated alternative UI successor, with **1.0.0** as the verified API snapshot. Core/themes are MIT-licensed and require no application license key, account or hosted service. Vuetify **4.3.x** remains preferred for new general-purpose UI; the authored Vue/Vuetify baseline remains **3.5.44 / 4.3.0**.
- Replaced obsolete component imports, licensing configuration, theme packages and upgrade guidance with OpenVue contracts. The dedicated Vite examples cover labeled Select, local preview Dialog and data-driven Carousel; Carousel uses `value`, an item slot and `v-model:page`, not compound carousel imports. Native root attributes use declared pass-through options under strict template checking.
- Removed hosted authentication SDK installation, credentials, login components, provider middleware and provider endpoint recipes. [Session boundaries](references/auth.md) now teach application-owned readiness, safe redirects, ephemeral token transport and identity retirement. These helpers do not implement server authentication or authorize protected data.
- Revised [Nuxt integrations](references/nuxt-integrations.md) to retain the local Vuetify/Pinia/Colada profile and explicit application-owned identity/cache contracts without a hosted service. Unknown identity and failed teardown remain closed; old callbacks must not populate a new identity's cache.
- Removed streaming provider-key collection/management. [AI streaming](references/ai-streaming.md) retains local client lifetimes and application-owned or self-hosted transport contracts, not hosted-model account setup. [VitePress](references/docs-vitepress.md) uses local search; the VueUse reader accepts an application-owned endpoint.
- Updated master discovery, architecture, routing, tooling, design, sources and public project documentation to match the service-independent scope. The **40-reference** index remains complete and directly discoverable.
- Completed fifth-pass reference corrections while preserving all 40 direct capability routes, conditional companions, architectural synthesis and first-class Nuxt ownership. Corrected bounded tween lifetimes, router search/deferred results, cache identity retirement, form submission/native bindings, VueUse target measurement and VitePress local indexing; application-owned service contracts and prior package removals remain unchanged.
- Tightened exact-release support boundaries rather than banning compatible incumbents. Excluded stock TanStack Vue SSR wrappers, defective VueUse component/directive adapters and motion-v custom-SFC wrapping that fails strict declarations; retained browser routing, owned core utilities, typed native motion tags and the incumbent Popmotion route.
- Made form/schema and production-catalog exclusions explicit: no Zod 4 through the vee-validate 4 Zod adapter, no v4 adapters alongside the v5 beta, no rejected/message-string FormKit rules and no compiler removal with raw I18n catalogs. Supported stable adapters, caught boolean rules and precompiled catalogs remain available.
- Fixed a production renderer crash from a motion-controller/template-ref name collision and corrected border-aware overflow comparison to use client dimensions. Recorded motion-v 2.8.0/core 15 full-declaration incompatibility; native recipes require an already accepted graph/compiler policy, never a weakened gate.
